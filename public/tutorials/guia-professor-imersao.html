Encontros 5 e 6 · uso local

Guia do professor

Roteiro de duas aulas para iniciantes: construir offline, testar, proteger, entregar e avaliar.

Offline-first3 chamadas no maximoConceitos A–D

Objetivo didatico

Tornar visivel o ciclo de um agente: escopo, contrato, construcao, teste, guardrail, observabilidade e limite de recursos.

Nao e objetivo: ensinar infraestrutura, Git ou deploy durante a imersao.

Regras da experiencia

  1. Toda entrega funciona com MOCK_LLM=1.
  2. O agente executa uma tarefa verificavel.
  3. A turma avanca por checkpoints coletivos.
  4. Falhas geram uma melhoria observavel.
  5. A API e opcional: ate tres tentativas por grupo.

O que roda em cada modo

Offline: nenhum modelo de IA. Uma funcao Python previsivel simula a resposta para validar fluxo, formato, guardrails e testes.

API opcional: Qwen/Qwen2.5-7B-Instruct roda no Hugging Face e exige internet e HF_TOKEN.

Por que usar o simulador

Ele separa duas dimensoes da atividade: engenharia do sistema e qualidade da resposta generativa.

O resultado deterministico permite localizar erros no fluxo antes que variacao, rede ou limite de API entrem na investigacao.

Nao chame o mock de IA local. Ele e um instrumento didatico sem modelo: comprova que o sistema funciona, mas nao que a resposta seja inteligente. Erros 429, 503, timeout ou token ausente nao reduzem a nota: volte ao simulador e continue.
Nunca coloque HF_TOKEN no HTML ou JavaScript. O GitHub Pages e estatico e nao protege segredos. Uma versao publica com IA real exigiria um backend autenticado com cota por usuario ou turma, limite de entrada e saida, timeout, cache, moderacao e monitoramento de custo. Para esta imersao, use a API apenas no portal local e sob orientacao.

Diagrama para apresentar em sala

Leitura em quatro movimentos: acompanhe primeiro a mensagem da esquerda para a direita; pare no bloco rosa para delimitar a autoria; compare simulador, API e cache; termine nas evidencias e no registro da nota.

Intervencoes

  • Se o escopo tiver “tudo”, reduza para um verbo.
  • Se a saida nao puder ser conferida, peca formato e limite.
  • Se metade travar, pare e resolva coletivamente.
  • Nao introduza token, Git ou deploy.

Entrega e avaliacao automatica

Aluno: criar o ZIP

python prepare_submission.py ^
  --id "12345" ^
  --nome "Nome Sobrenome" ^
  --agente "organizador-estudos"

O pacote contem apenas submission.yaml, agent.py e cases.yaml.

Professor: avaliar

  1. Execute python app.py.
  2. Abra a aba Entregar trabalho.
  3. Selecione o ZIP e avalie.
  4. Baixe notas.csv.

O historico completo fica em submissions/grades.db.

Seguranca: o avaliador bloqueia imports e operacoes perigosas, remove credenciais do ambiente e executa em subprocesso offline com timeout. Isso reduz riscos, mas nao e uma sandbox completa: use apenas no computador local da aula e nunca publique a aba de upload.
